## 文件定位

本文件用於定義「事件結果整合演化模型」中，各資料層級之間的轉換規則。

本規範不負責：

- 定義事件內容
- 判定案例邊界
- 設計資料表結構
- 評估任務品質

上述內容由其他規範文件負責。

本文件唯一目的：

> 確保事件資料在轉換為狀態、任務、結果與演化規則時，具備明確轉換條件，避免 AI 推論、資料污染與錯誤升級。

---

# 第一章　轉換核心原則

## 1.1 資料層級不可跳躍轉換

本模型採用：

```
Event
 ↓
State
 ↓
Task
 ↓
Feedback
 ↓
Evolution Rule
```

之單向主要轉換鏈。

禁止：

```
Event → Task
```

或：

```
AI 回覆 → Evolution Rule
```

等跨層直接推導。

所有高階資料必須保留來源鏈。

---

## 1.2 轉換必須具備來源依據

任何資料層級轉換時，必須保留：

- 原始來源資料
- 對應 ID
- 轉換原因
- 轉換狀態

若無法建立來源關聯：

標記：

```
Context_Insufficient
```

不得進行下一階段轉換。

---

# 第二章 Event → State 轉換規範

## 2.1 轉換目的

Event 層描述：

「發生了什麼」

State 層描述：

「事件造成什麼可觀測狀態」

兩者不可混合。

---

## 2.2 Event 形成 State 的必要條件

一個 Event 必須符合至少一項：

### A. 狀態改變

例如：

原本：

```
尚未建立資料解析器
```

事件：

```
完成 Parser 初版設計
```

形成：

```
State:
已存在 Parser 初版架構
```

---

### B. 環境改變

例如：

事件：

```
切換至本地端 AI 工作流
```

形成：

```
State:
執行環境由雲端轉為本地端
```

---

### C. 任務條件改變

例如：

事件：

```
新增驗證需求
```

形成：

```
State:
原任務增加驗證限制
```

---

## 2.3 禁止建立 State 的情況

以下不得建立 State：

- 單純意見交換
- 未形成事實的想法
- AI 提出的可能方案
- 未被確認的推論

例如：

AI：

「未來可能需要 Agent 架構」

不得建立：

```
State:
已需要 Agent 架構
```

---

# 第三章 State → Task 轉換規範

## 3.1 轉換目的

State 描述：

「目前處於什麼狀況」

Task 描述：

「需要進行什麼行動」

---

## 3.2 Task 成立必要條件

State 必須具備：

### 1. 明確問題或需求

例如：

```
目前缺少事件分割規範
```

---

### 2. 可執行方向

例如：

```
建立案例邊界規範文件
```

---

### 3. 預期產出

例如：

```
形成 v0.1 文件
```

---

## 3.3 禁止 Task 生成

以下不得建立 Task：

- 單純研究興趣
- 未決定執行方向的想法
- AI 建議但未被採納的方案

---

# 第四章 Task → Feedback 轉換規範

## 4.1 轉換目的

Task 描述：

「計畫執行」

Feedback 描述：

「執行後產生的結果」

---

## 4.2 Feedback 必須包含

至少一項：

- 實際產出
- 系統結果
- 人類確認結果
- 執行失敗結果

---

## 4.3 Feedback 分類規則

### TASK_RESULT

客觀執行結果。

例如：

```
完成文件 v0.1
```

---

### HUMAN_EVALUATION

人類主觀判斷。

例如：

```
使用者認為內容需要修改
```

---

### SYSTEM_RESULT

系統產生結果。

例如：

```
程式執行成功
```

---

## 4.4 禁止混合

不得將：

人類評價

轉換為：

客觀結果。

例如：

錯誤：

```
Feedback:
模型成功
```

來源：

「我覺得很好」

正確：

```
Feedback_Type:
HUMAN_EVALUATION
```

---

# 第五章 Feedback → Evolution Rule 轉換規範

## 5.1 轉換目的

Evolution Rule 不描述單次結果。

它描述：

「多次事件結果中形成的可重複模式」。

---

## 5.2 Evolution Rule 成立條件

至少需要：

### 條件一

存在完整鏈：

```
Event
 ↓
State
 ↓
Task
 ↓
Feedback
```

---

### 條件二

存在可觀察模式。

例如：

多次案例發現：

```
缺少任務邊界定義
會導致 AI 回覆範圍漂移
```

---

### 條件三

非單次偶然事件。

---

# 第六章 轉換阻斷規則

當發生以下情況：

## 1. 缺少來源

停止轉換。

標記：

```
Context_Insufficient
```

---

## 2. 只有推論

停止轉換。

標記：

```
Inference_Risk
```

---

## 3. 人類未確認

停止升級。

標記：

```
Need_Human_Confirm
```

---

# 第七章 完整轉換流程

```
原始事件資料
      |
      v
Event_Table
      |
      | Event → State 條件檢查
      v
State_Table
      |
      | State → Task 條件檢查
      v
Task_Table
      |
      | Task → Feedback 條件檢查
      v
Feedback_Table
      |
      | Feedback → Evolution 條件檢查
      v
Evolution_Rule_Table
```
